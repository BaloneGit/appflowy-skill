## 用例 4：计划文件执行（add -> rename -> delete）
为了避免影响业务字段，使用临时字段闭环验证：
- 新增：`M2_temp_field_1772508767`
- 改名：`M2_temp_field_1772508767_renamed`
- 删除：同一字段 ID

### 4.1 add（execute）
- plan 文件：`.tmp/v03_m2_plan_add.json`
- 结果：`executed_count=1`，创建字段 id：`c-33FN`

### 4.2 rename（execute）
- plan 文件：`.tmp/v03_m2_plan_rename.json`
- 结果：`executed_count=1`，字段 `c-33FN` 改名成功

### 4.3 delete 护栏验证（必须失败）
- 仅 `--execute --yes`：报错 `High risk operations detected... --allow-high-risk`
- 加 `--allow-high-risk` 但不加 `--allow-delete-fields`：报错 `Delete field operations detected... --allow-delete-fields`

### 4.4 delete（execute）
- 执行参数：`--execute --yes --allow-high-risk --allow-delete-fields`
- 结果：`executed_count=1`，字段 `c-33FN` 删除成功
- 收尾校验：字段 ID 不再存在（`field_exists=False`）

## M2 验证结论
- `apply-schema-migration` 已具备：
  - `--plan-file` 与目标 schema 直生两种模式
  - 默认 dry-run
  - `--execute --yes` 执行确认
  - 高风险与删除操作双护栏
  - before/after diff 摘要输出
- 当前保留限制：
  - `change_field_type` 仍默认人工处理，不自动执行
